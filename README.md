# Library Management System

## Project Description

A REST API backend application for managing library books, members, borrowing records, due dates, and fines.

The application supports three roles:

- **Member:** Search books, borrow and return books, and view borrowing history.
- **Librarian:** Add and update books, view all borrow records, and check overdue books.
- **Admin:** Manage members, delete books, and view reports.

## Installation and Setup

### 1. Clone the repository

```bash
git clone <repository-url>
cd library_management
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

### 3. Activate the virtual environment

For Git Bash on Windows:

```bash
source venv/Scripts/activate
```

### 4. Install required Python packages

```bash
pip install fastapi "uvicorn[standard]" sqlalchemy alembic pymysql pyjwt "pwdlib[argon2]" python-dotenv pytest httpx
```

### 5. Save installed dependencies

```bash
pip freeze > requirements.txt
```

## Purpose of Each File and Folder

| File/Folder | Purpose |
|---|---|
| `routers/` | Contains API endpoints grouped by functionality, such as authentication, books, and borrowing. |
| `routers/__init__.py` | Makes the routers directory a Python package. |
| `services/` | Contains business logic, including borrowing rules, returns, and fine calculations. |
| `services/__init__.py` | Makes the services directory a Python package. |
| `utils/` | Contains reusable utility functions for security and other common operations. |
| `utils/__init__.py` | Makes the utils directory a Python package. |
| `middleware/` | Contains middleware for processing HTTP requests and responses when required. |
| `middleware/__init__.py` | Makes the middleware directory a Python package. |
| `tests/` | Contains automated tests for API endpoints and business rules using Pytest. |
| `tests/__init__.py` | Makes the tests directory a Python package. |
| `main.py` | Creates the FastAPI application and registers API routers. |
| `database.py` | Configures the SQLAlchemy engine, MySQL connection, and database sessions. |
| `models.py` | Defines SQLAlchemy models for User, Book, and Borrow database tables. |
| `schemas.py` | Defines Pydantic schemas for validating incoming data and formatting API responses. |
| `dependencies.py` | Provides shared dependencies for identifying the logged-in user and checking role permissions. |
| `requirements.txt` | Lists the Python packages required to run the application. |
| `.env` | Stores environment-specific configuration, such as the database URL and JWT secret key. |
| `.gitignore` | Specifies files and folders Git should not track, such as `venv/`, `.env`, and cache files. |
| `Dockerfile` | Defines the instructions for building the application Docker image. |
| `docker-compose.yml` | Configures and runs the application and MySQL services together using Docker Compose. |
| `.dockerignore` | Specifies files and folders excluded from the Docker build context. |
| `README.md` | Documents the project, technology stack, setup instructions, and file structure. |
| `alembic/` | Generated by Alembic initialization; contains migration configuration and version scripts for database schema changes. |

### Additional Notes

- `routers/` handles HTTP-level operations, while `services/` handles business rules.
- `models.py` represents database tables, whereas `schemas.py` validates API input and output.
- `dependencies.py` helps protect restricted endpoints using authentication and role-based authorization.
- `.env` must not be committed to GitHub.
- The `alembic/` directory and its configuration will be generated when Alembic is initialized.
